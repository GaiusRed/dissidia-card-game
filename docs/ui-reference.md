# Arena-Style UI Review

This review records the desktop presentation against design section 10. It uses an interaction checklist instead of copied game artwork. The table keeps familiar card-game patterns while using original placeholder art.

## Reference checklist

| Area | Requested direction | Current implementation | Status |
|---|---|---|---|
| Table | Opponent above, own seat below, battlefield between | Four labeled rows: opponent Backups above Forwards; own Forwards above Backups, with both Forward rows toward the center. Player 1 and Player 2 have distinct row-edge accents. | Implemented for tested two-seat layouts |
| Hand | Bottom-center fan with playable cards emphasized | Tested sizes 0, 1, 5, 7, 10, and 19. Overflow scrolls horizontally; playable cards glow and can be clicked or dragged | Implemented for tested Character casting and hand sizes |
| Other playable zones | Same interaction model with source zone visible | Commander is a playable card beside the hand; its badge and tax-inclusive cost follow its rules object. Break Zone targets appear in a labeled tray for recovery abilities | Partial; only Commander and two Break Zone abilities use the extension |
| Targeting | Select a source, highlight legal targets, show a source-to-target arrow | Target drafts support Summons and activated abilities, legal hover snapping, cursor-follow arrows, target numbering, and revision | Partial; test every targeting mode and cancel path |
| Choices | Contextual buttons near the bottom-left | Choice dock is anchored at bottom-left; tests cover setup, mulligan, two-card discard, and damage allocation | Partial; live choice kinds are covered, but more card-specific effects and recovery paths remain open |
| Payment | Review costs and CP sources before submission | Editable payment dock shows cost/tax, generated/spent/remainder, required D/sacrifice components, and source selections; Forge Apprentice can be reviewed, targeted, confirmed, and resolved through the UI | Partial; Commander-tax, rejected-activation retention, and every element combination need browser coverage |
| Combat | Clear attack and block assignment | Party selection/revision, one blocker, block decline, confirmed damage allocation, and a First Strike blocker removal run through Playwright controls | Partial; other combat-state and card combinations remain open |
| Stack and history | Keep stack and game log visible without obscuring decisions | Center stack cards, ordered stack metadata (controller, source ability, targets, resolving status), and an accessible scrollable event log are present | Partial; test more source-departure and paused-resolution combinations |
| Menu and deck editing | Familiar compact controls with readable card list | Local menu, two preset decks, browser, and singleton editor | Partial |
| Cosmetics | No pets or board cosmetics | No pet slot or cosmetic board controls | Implemented |

## Review against the Arena direction

| UI state | Review | Intentional project difference |
|---|---|---|
| Idle table | Seat labels and edge accents show ownership. Backups and Forwards have separate rows. The Forward rows face the field center. | The game uses four labeled rows to show FFTCG Forward and Backup types. |
| Hover, cast, and target | Hand cards stay inside the viewport. The selected card shows full rules text. Target arrows and selected targets give direct feedback. | Costs use FFTCG CP, element, dull, and discard terms. |
| Choice and stack | The choice actor, reason, target, and source remain visible. Stack detail stays clear of the event log. | Contextual choices use the requested bottom-left dock. The rules use a Commander zone and seven-damage limit. |
| Editor | Card names, types, costs, rules text, and add/remove controls remain visible. Search and filters preserve focus. | The editor uses a compact singleton deck list for the 19-card playtest format. |
| Overflow | Hand sizes through 19 remain reachable. Hand and choice rows scroll when needed. | The test suite uses original placeholder card art rather than Arena art. |

The approved bright palette and FFTCG terms replace Arena's darker table and Magic-specific terms. Playwright is pinned to version 1.63.0 through the lockfile, and the UI-design workflow uses `windows-2022` to keep future visual evidence on the baseline platform.

## Known interaction gaps

- Payment UI tests cover editing a standard discard source, incomplete payment, explicit cast confirmation, Escape cancellation, an activated ability's cost/target review, rejected-choice retention, stale-draft clearing after match replacement, and an activated ability's resolution. Commander tax and the full element/payment matrix remain untested in the browser.
- The rules support Forward parties and one blocker. Party selection/revision, block/no-block, allocation, and a First Strike attacker defeating its blocker through actual UI controls have browser coverage.
- Cards outside the hand are not generally offered as playable cards; Commander presentation is the only extension currently wired to casting.
- Escape closes a selected-card inspector when no required choice owns input; tests pass across all viewports. Accepted-event feedback has normal and reduced-motion coverage. Full keyboard navigation and broader animation coverage remain incomplete.

- Accepted casts, target declarations, damage, departures, draws, and Commander returns map to presentation markers. Normal motion uses brief CSS feedback after an accepted host reply; reduced motion applies the same final state immediately. The Phaser canvas remains static.
